## 🧠 Core Idea

A verification URL is:

```

URL + data + signature + expiration

```

### Example

```

[https://example.com/verify?user_id=1&expires=123456&signature=abc123](https://example.com/verify?user_id=1&expires=123456&signature=abc123)

````

---

## 🔑 Components

### 1. Payload (data you want to verify)

This is the information you include in the URL:

- `user_id`
- `email`
- `action` (e.g. reset-password, verify-email, invite-user, etc.)

---

### 2. Expiration

Defines how long the link is valid.

```php
$expires = now()->addMinutes(10);
````

👉 After this time, the link becomes invalid.

---

### 3. Signature (Most Important)

This ensures the URL was created by your server and not modified.

```php
$signature = hash_hmac('sha256', $payload . $expires, $secret_key);
```

#### Explanation:

* `payload` → the data (user_id, action, etc.)
* `expires` → expiration timestamp
* `secret_key` → your app secret (e.g. APP_KEY)

👉 The signature guarantees:

* Integrity (data was not changed)
* Authenticity (generated by your server)

---

## 🔐 Final Structure

```
/verify?user_id=1&expires=123456&signature=abc123
```

### Breakdown:

* `user_id=1` → who the link is for
* `expires=123456` → when it expires
* `signature=abc123` → security protection

---

## 🧠 Mental Model

* **Payload** → What is being verified
* **Expiration** → Until when it is valid
* **Signature** → Ensures it was not tampered with
