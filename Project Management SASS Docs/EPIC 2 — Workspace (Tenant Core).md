- # EPIC 2 — Workspace (Tenant Core)
- ## Epic Scope
- Workspace lifecycle, membership, invites, and tenant isolation enforcement.
- 
- ## Feature 2.1 — Create Workspace
- ### User Story
- As a user, I want to create a workspace so that I can manage a team.
- ### Services / Actions Used
    - **Action:** `CreateWorkspace`
    - **Service:** `WorkspaceService` (workspace persistence)
    - **Service:** `MembershipService` (member creation + invariants)
    - **Service:** `RoleBootstrapService` (optional, if you copy template roles on creation)
- ### Domain Rules
    - Creator becomes a member immediately.
    - Creator becomes Admin immediately.
    - Workspace must always have at least one Admin.
- ### Tasks
    - **DB**
        - `workspaces` table: id, name, created_by_user_id, timestamps
        - `workspace_members` table: workspace_id, user_id, role_id, joined_at, timestamps
        - unique(workspace_id, user_id)
    - **API**
        - `POST /workspaces`
    - **Implementation**
        - `WorkspaceService::create(...)`
        - `MembershipService::addMemberAsAdmin(...)`
        - (optional) `RoleBootstrapService::copyTemplateRoles(workspace)`
    - **Tests**
        - creator is member
        - creator is admin
        - unique membership enforced

- ### Tasks

        - `GET /workspaces`
    - **Implementation**
        - query via `workspace_members`
    - **Tests**
        - returns only my workspaces

- ## Feature 2.3 — Workspace Context Validation (Tenant Boundary)
- ### User Story
- As the system, I want strict workspace context validation so that tenant isolation is guaranteed.
- ### Services / Actions Used
    - **Middleware:** `WorkspaceContextMiddleware`
    - **Service:** `WorkspaceContextService` (resolve workspace + membership and store context)
- ### Domain Rules
    - Missing header => 400
    - Invalid header => 400
    - Workspace not found => 400
    - Not a member => 403
- ### Tasks
    - **Middleware**
        - read `X-Workspace-Id`
        - validate format
        - load workspace
        - verify membership
        - store context (workspaceId, memberId, roleId) for later use
    - **Tests**
        - missing header = 400
        - non-member = 403
        - member passes
- 
- ## Feature 2.4 — Automatic Tenant Scoping (Global Model Scope)
- ### User Story
- As the system, I want tenant filtering automatic so developers cannot forget it.
- ### Services / Actions Used
    - **Trait:** `BelongsToWorkspace`
    - **Service:** `WorkspaceContextService` (provides current workspace id)
- ### Domain Rules
    - Any tenant-owned model must always query by workspace_id.
    - workspace_id must be auto-filled on create.
- ### Tasks
    - implement global scope using `WorkspaceContextService::currentWorkspaceId()`
    - auto-set workspace_id on creating
    - apply trait to all tenant models (projects/tasks/comments/notifications/audit/history/etc)
    - tests: cannot query cross workspace by guessing ids

- ## Feature 2.5 — Invite Member (Create Invite)
- ### User Story
- As a workspace admin, I want to create an invite token so that a user can join.
- ### Services / Actions Used
    - **Action:** `CreateWorkspaceInvite`
    - **Service:** `InviteService` (token generation + persistence)
    - **Service:** `MembershipService` (validation helpers)
    - **Service:** `AuthorizationService` (permission check hook; from RBAC epic later)
- ### Domain Rules
    - Token must be cryptographically secure.
    - Invite must expire.
    - Invite cannot be reused.
    - Invite may be restricted by email.
- ### Tasks
    - **DB**
        - `workspace_invites`:
            - workspace_id
            - token (unique)
            - email (nullable)
            - role_id (nullable/default)
            - created_by_user_id
            - expires_at
            - used_at
            - timestamps
    - **API**
        - `POST /invites` (workspace-scoped; header required)
    - **Implementation**
        - `InviteService::createInvite(workspace, email?, role?, expiresAt)`
    - **Tests**
        - admin can create
        - non-admin forbidden
        - token uniqueness
-

- ## Feature 2.7 — Accept Invite
- ### User Story
- As a user, I want to accept an invite so that I join the workspace.
- ### Services / Actions Used
    - **Action:** `AcceptWorkspaceInvite`
    - **Service:** `InviteService` (atomic accept + mark used)
    - **Service:** `MembershipService` (create membership + invariants)
- ### Domain Rules
    - Accept must be atomic (no double accept).
    - Email restriction must be enforced if set.
    - If already member:
        - either reject, or update role (choose one rule and keep it consistent).
- ### Tasks
    - **API**
        - `POST /invites/{token}/accept` (global)
    - **Implementation**
        - transaction:
            - validate invite
            - enforce restriction
            - create membership
            - mark invite used
    - **Tests**
        - accept creates membership
        - cannot accept twice
        - email restriction enforced
- 
- ## Feature 2.8 — Member Management (View / Role Change / Remove)
- ### User Story
- As an admin, I want to manage members so that workspace access is controlled.
- ### Services / Actions Used
    - **Action:** `ListMembers`
    - **Action:** `ChangeMemberRole`
    - **Action:** `RemoveMember`
    - **Service:** `MembershipService` (last-admin rule enforced here)
- ### Domain Rules
    - Workspace must always have at least one Admin.
    - Removing the last Admin is forbidden.
    - Self-demotion must not violate admin minimum rule (recommended).
- ### Tasks
    - **API**
        - `GET /members` (scoped)
        - `PATCH /members/{userId}/role` (scoped)
        - `DELETE /members/{userId}` (scoped)
    - **Implementation**
        - `MembershipService::ensureNotLastAdmin(...)`
        - `MembershipService::changeRole(...)`
        - `MembershipService::removeMember(...)`
    - **Tests**
        - last admin cannot be removed
        - role change works
        - viewer/non-admin forbidden
